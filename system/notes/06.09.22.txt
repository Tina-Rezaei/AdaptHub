-> Purpose: also a finite set, how do you envision that a new app or new device may be installed for a new purpose? This seems to be more of something that is purely informational to the user (structured text) but is not processed automatically (or even used) by the access control engine. Or is it?

-> Example Doorman app: it seems the trigger is that a FaceRecognitionResult event is triggered. Should we make this explicit in the model? E.g. : ON FaceRecognition f IF f.result == "unknown" (I don't know if this complies completely with the TA model though).

Sending the alert to the phone is not a system call so you must trust the app to actually do what it said it'll do. Maybe something simpler like allowing the app to access an online service at some end point would be enough (that the level of what we can control).
-> For the LightController app, do we need TABAC rules? It seems that regular TA rules could be used to control the lights, without requiring to give access to anything to an application. It is when the voice recognition software running locally does not get to understand the command that we must give it explicitly access to online services able to use more sophisticated models.
